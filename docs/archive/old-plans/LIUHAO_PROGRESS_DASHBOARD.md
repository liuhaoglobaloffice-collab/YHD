### Token操作流程示例

```yaml
【场景1: 主账号直接使用】
1. 主账号发起任务 (需要100 Token)
2. 检查主账号Token池: 10,000 → 9,900
3. 执行任务
4. 日志记录: "Master账号使用100 Token"
5. 主账号可见: ✅ 真实记录

【场景2: 主账号"偷用"子账号Token】
1. 主账号Token不足,但需要执行任务
2. 系统自动选择Token最多的子账号 (子账号A)
3. 从子账号A的Token池扣除 (5,000 → 4,900)
4. 执行任务
5. 日志记录:
   - 主账号视图: ✅ "偷用子账号A的100 Token"
   - 子账号A视图: ⚠️ "系统任务消耗100 Token"
6. 子账号A: 完全不知道被主账号偷用

【场景3: 子账号正常使用】
1. 子账号A发起任务 (需要50 Token)
2. 检查子账号A Token池: 4,900 → 4,850
3. 执行任务
4. 日志记录:
   - 子账号A视图: ✅ "我使用了50 Token"
   - 主账号视图: ✅ "子账号A使用了50 Token"

【场景4: 子账号A试图访问子账号B】
1. 子账号A尝试查询子账号B的Token
2. 系统拦截: ❌ "权限不足"
3. 子账号A只能看到自己的数据
4. 安全隔离生效

【场景5: Token池充值】
1. 方式1: API Key充值
   - 主账号添加OpenAI/Claude API Key
   - Token池自动计算额度
   - 分配给主账号或子账号

2. 方式2: 主账号手动分配
   - 主账号将自己的Token转给子账号
   - 主账号: 10,000 → 9,000
   - 子账号A: 5,000 → 6,000
   
3. 方式3: 子账号独立充值
   - 子账号A添加自己的API Key
   - Token增加到子账号A的池
   - 主账号依然可以偷用
```

### 为什么这是最完美模式?

```yaml

   - 阶段1: 快速验证,失败成本低
   - 阶段2: 有了基础再投资硬件
   - 阶段3: 已有经验,风险最小
   - 阶段4: 自然演进,水到渠成

2. 成本优化:
   - 阶段1: $200/月 × 2月 = $400
   - 阶段2: $2,500硬件 + $50/月 × 3月 = $2,650
   - 阶段3+: $15/月 × 永久 = 最划算
   - 总投资: ~$3,200 (2年内回本)

3. 价值递增:
   - 阶段1: 验证商业价值 (最重要!)
   - 阶段2: 降低成本80%+
   - 阶段3: 经济独立
   - 阶段4: 持续增值

4. 灵活适应:
   - 每个阶段都可独立运行
   - 可随时暂停/调整
   - 可根据反馈优化
   - 不被技术路线绑架

5. 长期可持续:
   - 不依赖外部API
   - 不怕服务商倒闭
   - 不怕价格上涨
   - 真正的"拥有"而非"租用"
```
